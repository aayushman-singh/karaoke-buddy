## Architecture Summary (read this before touching anything)

Five nodes wired through the UI. A single pure function `build_filter_chain(pitch_semitones, vocal_reduce_percent)` is the **only** place audio-math lives — both the live player and the exporter call it.

```
UI  →  Source Resolver  →  (local file or yt-dlp download)
UI  →  Player (libmpv)  →  set_filter(build_filter_chain(...))
UI  →  Exporter (FFmpeg subprocess)
UI  ↔  Library (library.json, atomic write)
```

Key implementation details in the **actual** code (not the plan's templates):
- `Library` persists as a flat JSON array `[{...}, ...]`, not `{"entries": [...]}`.
- `Library.list()` returns entries sorted by `last_opened` descending.
- `Library.touch(entry_id, pitch, vocal_reduce)` updates settings + `last_opened`.
- `Library.find_by_source(source)` finds by URL or local path.
- `ExportThread(input_path, output_path, pitch_semitones, vocal_reduce_percent, duration_seconds, ffmpeg_exe)` — calls `build_filter_chain` internally.
- `DownloadWorker` uses `resolve_local` / `resolve_youtube` from `core/source_resolver.py`.
- `Player` has a `PlayerError` exception and lazy `initialize(wid, libmpv_path)` pattern.
